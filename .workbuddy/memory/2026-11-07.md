## 修正路径表述错误（AppData/extensions → 用户数据存储位置）

用户指出文档里「拓展代码保存在 AppData/extensions/」地址有误。核查确认：

**真实路径由 `core/store.py` 的 `ROOT` 决定**（默认 `%LOCALAPPDATA%\AgentCluster`，
可在设置中心「数据存储」自定义，自定义值写在项目根 `.storage_location`）。
`backend/api/extensions.py` 里 `EXT_ROOT = _store.ROOT / "extensions"`，
所以是 `<数据目录>\extensions\`，**不是**项目内的 `AppData/extensions/`（那是旧版遗留目录，
`store.py` 里有 `_LEGACY_APP_DATA` 专门做迁移）。

实测本机：`C:\Users\yangq\AppData\Local\AgentCluster\extensions\`，
含 EXTENSION_SPEC.md / extensions_market.json / installed.json / _builtin/ 及 5 个已装拓展。

同类错误还有 `backgrounds/spec.md`（背景动画规范），也在数据目录下。

**改动**：
- `frontend/src/views/ExtensionManagement.vue`：文案改为「数据存储位置的 extensions\ 目录下」
- `frontend/src/views/Settings.vue`：背景规范文案同样修正；**路径表补上「🎨 自定义背景」
  与「🧩 功能拓展」两行**（原先只列 7 项，用户在界面上根本看不到 extensions 路径）
- `backend/core/store.py`：`get_store_paths()` 增加 `extensions_dir` 字段
- `使用说明.md`：第十章与末尾路径表同步修正

**注意**：后端加字段需重启后端才生效；前端改动需重新 build（Electron 托管 dist/）。


## 市场下载资源重名加序号（画布 / 智能体分组）

用户需求：从市场下载的画布资源，若**画布名**或**智能体分组名**与本机重名，
自动加序号区分（游戏团队 → 游戏团队2）；**重名智能体不改名**，但 id 不能冲突。

**改动**：`backend/api/market.py`
- 新增 `_unique_name(base, taken)`：重名时加序号；名称自带数字后缀时按尾部数字递增
  （游戏团队2 → 游戏团队3，而不是游戏团队22）；纯数字名直接递增（2024 → 2025）。
- 新增 `_alloc_local_id(domain)`：在 `store.next_id` 基础上复查占用，杜绝覆盖本机已有记录。
- 新增 `_install_lock`：安装全程串行，避免并发安装撞号。
- `_install_canvas` 重写为四步：① 分组按 `_unique_name` 加序号**新建**（不再复用本地同名组，
  下载来的智能体归自己的组）② 智能体一律新建、名字保持市场原样、id 全新
  ③ 节点按 `agent_key` 精确匹配翻译 agent_id ④ 画布名加序号。
- `_install_agent`：名字不改，id 用 `_alloc_local_id`。

**关键坑（发布侧）**：画布节点原本只用 `agent_ref`（智能体**名字**）引用智能体，
画布内出现两个同名智能体时，节点会全部绑到同一个智能体上（串位）。
修复：发布时为每个智能体分配画布内唯一键 `agent_key`（= 唯一目录名），
写进 agent.json、canvas.json.agents 和节点的 `agent_key` 字段；
安装侧优先按 `agent_key` 匹配，无 key 的旧包按名字**按序**取用，同样不串位。

**「已安装」判定**：画布改名后名字对不上，改用安装时写入的 `market_id` 作权威判定，
名字匹配仅作旧数据兜底。

**前端**：`views/Market.vue` 下载提示改显示实际落地名 + 新建分组列表。

**测试**：`backend/tests/test_market_install_rename.py`（12 项，含发布→安装闭环）。
注意：测试必须同时 monkeypatch `MARKET_ROOT` 和 `INDEX_FILE`——后者是模块加载时求值的常量，
只改 MARKET_ROOT 会把测试条目写进**真实市场仓库**（本项目 `../market`）。
同理 pytest 在本机需用 `--basetemp=./.pytest_tmp`（默认临时目录会被沙箱拦截清理）。

**环境**：本机真正跑后端/测试的 Python 是 `F:/anaconda3/python.exe`（含 fastapi + pytest），
WorkBuddy 自带 python 与系统 Python313 都没有 fastapi。
