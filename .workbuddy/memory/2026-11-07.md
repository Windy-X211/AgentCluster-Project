### 顺手挖出的真实 bug（静默、恒定失效）

`core/commands.py::_effective_workdir()` 里：

```python
_DEFAULT_WORKDIR_CACHE = {"path": dwd, "at": now}   # ← 函数内赋值 = 局部变量！
```

Python 规定：函数体内**任何**赋值都会让该名字在整个函数里成为局部变量，
于是上面这行让 `_DEFAULT_WORKDIR_CACHE` 变成局部名 → 读取时抛
`UnboundLocalError` → 被下面的 `except Exception: pass` **静默吞掉** →
`default_workdir` 兜底**从未真正生效过**（实测恒返回 None）。

**修法**：缓存必须**原地更新字典**（`cached["path"] = dwd`），不能重新绑定名字。
配套加了 `invalidate_default_workdir_cache()`，设置改动后立即失效（否则最多延迟 2s TTL）。

> 教训：模块级缓存字典在函数里**只改内容、不改名**。这个 bug 被 `except: pass`
> 藏了不知多久——以后看到「模块级 dict + 函数内赋值」的组合要警觉。

## 修复：智能体写长文件时后端 failed（事件循环被写文件参数占死）

**现象**：智能体调用 `file.write` 写长文件（报告/文档）时后端 failed / 托盘显示后端 FAIL。
`backend/diag/stall-*.log` 的调用栈直接指向 `core/llm.py:817` → `validator.feed(arg_chunk)`。

**根因 1：流式参数校验器是 O(n²)，且正则灾难性回溯**
`core/tool_stream_validator.py` 的 `feed()` 每收一个 chunk 就把**已累积的全部参数**
重新 join + 逐字符重扫 + 跑一遍嵌套量词正则
`("(?:[^"\\]|\\.)*"\s*:\s*)(?!")...`（键侧含嵌套量词）。
- 12KB 参数：feed 全程 33.78s；单次 feed 延迟 500ms → 直接占死事件循环。
- 141KB 参数：单次正则 sub 要 36 秒。

**根因 2：tool_call.arguments 完整回灌给 LLM**
写完文件后，完整文件内容存在 `tool_calls[].function.arguments` 里，原样落库，
并在**之后每一轮**都作为 assistant.tool_calls 回灌给模型。90KB 文件 = 每轮烧 90K token
→ 上下文爆掉 → 上游返回 400 → 整轮失败。

**根因 3（本次补修）：`agent_runtime._execute_tool` 里还有一份旧正则副本**
`core/agent_runtime.py` 的嵌套函数 `_fix_bare_identifiers` 自带正则实现，
在「JSON 解析失败 → 回退修复参数」路径上必然被调用（写长文件时经常触发）。
12KB 参数实测 323ms。

**修复**：
- `core/tool_stream_validator.py`：重写为**跨 chunk 增量状态机**（`_ArgScanner`），
  平衡性与裸标识符都只扫新到的字符，O(n) 总复杂度；`fix_bare_identifiers` 改为
  单遍线性扫描；伪协议检测加 64 字符重叠窗口（顺手修掉跨块漏检的既有缺陷）。
  - 12KB feed：33.78s → 0.01s（**5176x**）；单次 feed 延迟 500ms → 1.7ms。
  - 顺带修掉 OLD 对 `true`/`false`/`null` 半截前缀的误报（旧实现会把 `{"flag": t` 判成裸标识符）。
- `core/agent_runtime.py`：新增 `TOOL_ARGS_LLM_MAX_CHARS = 2000` +
  `_trim_tool_call_arguments` / `_trim_tool_calls_for_llm`，
  **只裁剪发给 LLM 的副本**（保留键结构与短值），落库/前端那份保持完整；
  `_execute_tool` 的本地 `_fix_bare_identifiers` 改为复用线性实现，删掉正则副本。
  - 400KB 文件回灌 token：143811 → 1638（恒定）。
- `backend/tests/test_long_file_write.py`：新增 57 个回归测试。

**验证**：`139 passed, 2 skipped`；端到端 400KB 文件单次 feed 延迟 0.3ms、
回灌 token 恒定 1638、落库完整、回灌参数仍是合法 JSON。

**结论**：事件循环不再被长文件参数占死，「写长文件 → 后端 failed」闭环解除。

## 经验：git push 报 CRYPT_E_NO_REVOCATION_CHECK 的解法

**现象**：`git fetch` / `git push` 全部失败：
```
fatal: unable to access 'https://github.com/...': schannel: next InitializeSecurityContext
failed: CRYPT_E_NO_REVOCATION_CHECK (0x80092012) - 无法验证证书吊销状态
```

**根因**：本机装了 SteamTools（BeyondDimension 的 HTTPS MITM 代理），它用自签的
`CN=SteamTools Certificate` 根证书给所有 HTTPS 流量重签证书。
- schannel 后端：吊销检查拿不到 CRL → 报 0x80092012
- openssl 后端：报 `unable to get local issuer certificate`（默认 CA 池里没有 SteamTools 根）
- `http.schannelCheckRevoke=false` **无效**（不解决 schannel 的整条链路）

**解法**：把 SteamTools 根证书从 Windows 证书库导出为 PEM，配给 git 的 openssl 后端。
用 PowerShell 工具导出 DER（`Get-ChildItem Cert:\CurrentUser\Root` 找 Subject 含
SteamTools 的项 → `Export('Cert')` 写文件），再 `openssl x509 -inform DER` 转 PEM，
然后：
```
git -c http.sslBackend=openssl -c http.sslCAInfo=<root.pem> push origin main
```
证书指纹 `FEBC3190FC1B0AD3D5B1FECF8DF70F3C0C4ECE3F`，有效期至 2027-07-29。

**注意**：用 `-c` 临时参数即可，**不要**写进全局 git config（避免影响其他项目）；
导出的 .cer/.pem 不要提交进仓库。

## 经验：Windows 上按 hunk 拆补丁必须用 newline=""

用 Python `Path.write_text()` 写补丁文件时，Windows 会把 `\n` 转成 `\r\n`，
导致 `git apply` 的上下文匹配全部失败（报 "patch does not apply"，
且**连完整补丁也会失败**，容易误判为补丁本身有问题）。
必须 `open(out, "w", encoding="utf-8", newline="")`。

另外：`git diff` 产出的是「索引 → 工作区」的补丁，要应用到索引必须加 `--cached`，
否则 `git apply --check` 必然失败（因为工作区已经包含这些改动了）。

## 调色板交互调整：去掉「确定」+ 浮窗可拖动

用户反馈两点：① 选中颜色不需要点确定，可直接给节点上色；② 浮窗可以拖动改变位置。

### 改动

**`components/ColorSpectrumPopover.vue`（事件契约整体改了）**
- `confirm`(提交) / `cancel` / `reset` → **`change`(实时生效) / `close` / `update:pos`**。
- 「确定」「取消」两个按钮**删除**，只留「↺ 自动配色」「关闭」。
- 拖色相条、拖 SV 方块、点预设色 → 每次都 `emit('change', hex)`，
  **实时**生效：画布上悬停的节点立刻预览该色，点节点即上色。
- 浮窗位置由父级持有（`pos` prop + `update:pos` 事件），组件内另存 `localPos`
  做即时跟手；`watch(props.pos)` 在**非拖动中**时同步，避免与拖动打架。
- 标题栏变拖动把手（`pointerdown` + `setPointerCapture` + `e.preventDefault()` 防选中文本），
  拖动时 `clampPos()` 贴边保护，浮窗不会被拖出视口。
- 位置变更 `emit('update:pos')` → 父级记下并置 `palettePosUserSet`，
  **下次打开沿用用户拖过的位置**，而不是回到按钮下方。

**`components/CanvasBoard.vue`**
- `onColorConfirmed` → `onColorChanged`：只更新 `pickedColor`，**不再关闭浮窗**（可连续上色）。
- 新增 `onPaletteMoved` / `palettePosUserSet`。
- Esc 语义改为**彻底退出调色**（关浮窗 + 清待应用色），一步到位。

### 关键交互决策

**点画布空白不关闭浮窗**（只关浮窗会打断"连续给多个节点上色"）。
浮窗可以被拖到不挡节点的位置 → 选一次色 → 连点多个节点。
关闭方式收敛为三种：✕ 按钮 / Esc / 再点工具栏 🎨 按钮。

### 验证（Playwright，10 项全过）

① 无「确定」按钮 ② 拖动位移精确 (dx=300 dy=150) ③ 选色即实时生效（提示条出现）
④ 悬停节点实时预览 ⑤ 连续给 3 个节点上色且浮窗始终开着
⑥ 点空白浮窗不关闭 ⑦ ✕ 关闭 ⑧ 重开沿用拖动位置 ⑨ Esc 彻底退出 ⑩ 自动配色清空。

测试动过的真实数据（agent 8 / 41 / 28-30）**已全部还原**。
（agent 42「绘图需求策划师」的 `#28e267` 是用户自己在跑起来的应用里手动选的，
