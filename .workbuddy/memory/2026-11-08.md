## 修正：直角折线改为「只有一个折角」的 L 形

用户反馈 4 拐点阶梯太绕，要求整条线只有一个 90° 折角。已重写几何：

- 删除 `elbowPoints`（H-V-H-V-H 阶梯）与 `ORTHO_STUB`，改为 `lShape(p, q, horizontalFirst)`：拐角取 `(q.x, p.y)` 或 `(p.x, q.y)`，三点两段，共线时 dedupe 自动退化成直线。
- 新增 `orthoAnchors(a, b, bias)`：为 L 形选**互补边**——水平距离为主时源取左右侧、目标取上下侧（先水平后垂直）；垂直为主时反过来；两端中心共线时取同一对侧边直接一条直线（0 折角）。这样两段都沿节点边缘法线正出正入。
- 双向共线时用 `bias`（±16px）沿边缘错开锚点；非共线时两个方向的 L 形天然分离，不再需要通道偏移。
- `orthoRoute` 签名改为 `(p1, p2, horizontalFirst, wps)`；`tempPath` 预览改用 `lShape`。
- 边界：两节点的投影区间重叠且贴得很近时，单折角 L 形在几何上无法同时避开两个节点，线可能贴/穿过节点；未加 2 拐角 fallback，以保持「只有一个折角」的要求。

验证：从真实组件源码抽取几何函数跑 132 项断言全通过（四对角方向恰好 1 折角且两端正出正入、共线 0 折角、双向分离 32px、控制点、插入柄语义）；Electron 四主题渲染截图确认对角/垂直主导 `corners=1, oblique=0`、水平共线双向 `corners=0`；构建通过。

## 连线避让：曲线 / 直角折线绕开其他智能体节点

需求：除「斜线直连」外，另两种连线尽量不要穿过其他智能体节点。

实现（`CanvasBoard.vue` 新增一整套避让层）：
- `avoidRects(a, b)`：其它节点外扩 10px（绕行后留间隙）、起止节点内缩 6px（贴边不算穿体、切进内部才算）。
- `segRectLen`（Liang–Barsky 线段裁剪）→ `routeHits` 返回**被穿过的节点个数** + 累计穿越长度。注意：不能用「段-矩形相交次数」当指标，绕行后采样段更多会让它虚高（改前随机回归 15/120 假报恶化，改成 distinct rect 后 0）。
- 曲线 `detourCurve`：每个原始段插入 2 个沿法线抬升的控制点（28%/72%），幅度 = 挡路矩形在法线上的投影外沿 + 16px；4 档 gain × 2 侧扫一遍，按 score 选最优；返回 `[p0,a,b,p1,...]` 让插入柄能按原始段序号精确映射。曾试 3 个抬升点（25/50/75%）想压过冲，实测弧反而更宽更笨，已回退。
- 折线 `detourOrtho`：在**保持只有一个折角**的前提下搜索候选——两种「先横后竖/先竖后横」× 四种出边 × 四种入边 × 若干锚点坐标（居中/贴边/挡路节点边缘外侧，≤6 个）。评分 = 穿节点数×1000 + 穿越长×2 + 逆着目标方向出/入各罚 350 + 偏离默认朝向 20 + 路径长×0.02。无障碍时直接走原 `lShape`（快速路径，外观零变化）。
- **兜底原则**：绕行只有严格更干净才生效（`n*10000+len*5` 比较），否则保留原路径 → 随机 120 组布局下穿节点数从不增加。
- 双向避让：`sidePref` 恒取 +1（反向线的法线方向相反，天然落到遮挡另一侧）；之前用 `from_node < to_node` 定符号会被法线翻转抵消，两条线跑到同一侧。
- 带手动控制点的曲线同样绕行，且曲线仍严格穿过每个控制点；带控制点的折线逐段在两个 L 朝向里挑更干净的那个。
- `tempPath` 拖拽预览同步避让（同样的「更干净才改」判定）。
- **斜线直连完全不参与避让**（按需求保持原样，仍会穿过节点）。

顺带修掉一个原有 bug：两节点近乎水平相邻时（|Δcy| < 40），默认 L 形的水平段会横切进目标节点本体；现在候选搜索会选到「从源右侧 y=a.y+10 出、横到目标左上角 x 附近、再垂直接入目标顶边」的干净 L。

验证：从真实源码抽函数跑 27 项断言全通过（无障碍回归不变形、遮挡时曲线/折线均 0 穿透且端点仍在节点边缘、恰好 1 折角全轴对齐、水平相邻不切进目标、带控制点仍穿过控制点、双向分离、斜线直连不变、随机 120 组从不更糟）；Electron 四主题 × 四场景渲染截图逐列确认；`vue-tsc` + vite 构建通过。

## 画布直角折线（ortho）重新设计

需求（用户先确认理解、回复「好的」后执行）：包围盒内无其他节点时提供顺 / 逆时针两条 L；一侧被挡自动切换方向，两侧被挡增加拐点绕行；拖动拐点时锚点跟着动且线最短；锚点落不到节点上时自动增加拐点；禁止自交；控制点严格为拐点；拖动节点时拐点重合消除多余线。

实现（算法全部写在 `CanvasBoard.vue` 内，未新建文件）：
- 新核心 `routeOrthoEdge`：`orthogonalize`（相邻点不同 x/y 时自动插 L / Z 拐点；`turnFlags` 保证用户拐点必为 90° 折角）、`simplifyOrtho`（去重 / 合并共线 / 消折返）、`selfCrossCount`（非相邻段相交与共线重叠）、`orthoCandidate`（16 种出入边组合 + 锚点正交投影派生）、`detourCandidates`（通道采样生成 Z / U 绕行）、分级筛选（不自交 > 不穿节点 > 保留用户拐点），所有候选都自交时忽略手动拐点重规划。
- 锚点是派生量，沿节点边 clamp 投影（`ORTHO_MARGIN=10`），不存 `waypoints`；方向偏好存 `edge.ortho_dir`，连线右键菜单「切换折线方向」。
- `startEdgeHandleDrag` 先固化渲染拐点再拖；insert 柄按段法线凸起 `ORTHO_BULGE=24`，保证新控制点一插入就是折角；`endEdgeDrag` / `endDrag` 用 `commitOrthoGeometry` 回写化简结果（已验证收敛，第二轮即稳定）。
- 切到 ortho / 新建 ortho 连线不再注入默认拐点，改为清空 `waypoints` 走自动布线。

改动文件：`frontend/src/components/CanvasBoard.vue`、`frontend/src/views/Market.vue`（缩略图同步「waypoints 即折角」语义）、`frontend/src/stores/canvas.ts`（CanvasClipboard 类型）、`backend/api/canvases.py`（Edge 增加 `ortho_dir`，否则 Pydantic `model_dump` 会丢字段）。工作区其它既有未提交改动未触碰。

验证：`npm run build`（vue-tsc -b + vite build）通过；7 个定向几何场景 + 400 组随机压力测试（硬约束：无斜线段 / 无自交 / 锚点落边 / 中间点全折角，0 错，平均单次 0.55ms）；固化收敛性验证通过。极端随机拐点顺序下约 22% 手动用例因「保持顺序数学上必然自交」触发重规划降级，属预期行为。

## 后续：改一条折线方向导致其他线联动（同日，真实根因）

store：把上一轮 `ortho_dir` 本地缓存泛化成「方向 + 锚点」偏好缓存（`rememberEdgePrefs` / `restoreEdgePrefs`，沿用旧 key 并兼容旧纯字符串格式），否则新增字段同样会被未重启后端吞掉，拖完一保存就丢。
关键修复：随机压力测试发现手动拐点顺序与入边冲突时，`orthogonalize` 兜底插点不保证末段方向，被 `strict=false` 候选选中 → 「末段非正入」。加「手动锚点方向为任何候选都必须满足」的硬检查，并给 `orthogonalize` 加 `forceTail` 参数（仅终点手动锚点时启用）用确定性 3/4 段交替折线保证正入，避免退化成「牺牲全部用户拐点」的自动布线。
验证：`npm run build` 通过；四边吸附 / t clamp / 离角留白 / 节点平移跟随 / 16 组出入边精确落点+正出正入 / 拖拐点锚点固定 / 阻挡场景全过；交互断言（两端互不干扰、不固化、双击与菜单恢复、切线型清理、方向不受影响）与 store 断言（旧后端保存与刷新保留、恢复默认不复活、服务端值让位、旧格式缓存兼容、映射检查）全过；压力测试 A 300 组带随机锚点 + B 400 组无锚点回归，硬约束均 0 错，平均 0.88 / 0.39ms，拐点重规划消除率从 47% 降到 29%（B 为 27%，属极端随机绕圈拐点的固有自交降级）。
约定：手动锚点优先于「拖拐点时锚点跟着动」；`Market.vue` 是圆形节点简化缩略图，不体现手动锚点；后端需重启才能把新字段持久化到服务端，未重启时靠本地缓存维持本次浏览器内。

## 新功能：逐段绘制连线（每段线型可不同）

需求：点节点「连线」按钮，从靠近鼠标的边上点起笔；右键菜单选曲线 / 直线 / 圆弧；左键落点确认一段并可继续画，每段线型独立；最后点节点，以距鼠标最近的边上点收笔。

实现（`CanvasBoard.vue`，未新建文件）：
- 新增 `shape='mixed'` 与 `edge.segments`：`[{type:'straight'|'curve'|'arc', end:{x,y}, ctrl:[2点], bulge:有符号归一化矢高}]`。顶点序列 = [起点锚点, 各段 end, 终点锚点]；首末锚点沿用 `{side,t}` 相对值（节点移动自动跟随），中间顶点/曲线控制点是画布绝对坐标，节点拖动时由 `dragSegments` 一起平移。
- 几何：`buildSegment` 输出 SVG 片段 + 采样（L / C / A）。圆弧为真圆弧：`R=len(1/(8|b|)+|b|/2)`、圆心在弦中点法线另一侧，`b>0→sweep=0`、`b<0→sweep=1`，`largeArc=0`；用 SVG 规范 F.6.5 反算圆心校验过与采样一致。右键位置经 `viaBend`（沿弦 t + 法向垂距 s）烘焙成 `bulge≈s/(4t(1-t))` 或曲线控制点的法向平移，落点确认后段数据与菜单位置解耦。
- 交互：删除旧 `linking` / `tempPath`（按住按钮拖到节点的旧手势），改为点击式 `draw` 状态；起点锚点在确认第一段前随鼠标动态取 `closestEdgeAnchor`，确认后冻结；`drawPendingEnd` 悬停别的节点时贴最近边点；`openSegMenu` 拦截三个既有右键菜单，菜单期间冻结预览终点；Esc / 取消 / 撤销快照都会清空 draw；`startPan` / `startDrag` 在绘制时让位。
- 编辑：渲染出顶点 / 曲线控制点 / 圆弧矢高 / 拆分四类柄（`EdgeHandle` 加 `seg`/`ctrl`），双击顶点删段，`splitDrawSegment` 用 de Casteljau（曲线）与半弧角矢高 `b'=(1−cos(Δ/4))/(2sin(Δ/4))`（圆弧）保持形状不变地拆段；菜单「中点拆出新的一段」「清除分段路径」；切换 / 批量切换线型清除 `segments`。
- 数据：后端 `EdgeSegment` 子模型 + `Edge.segments`；store 的偏好缓存扩展成「方向 + 锚点 + 分段」，旧后端未重启吞字段时按画布 id + 边 id 逐条补回，缓存被每次保存重建所以清除不会复活；剪贴板 / 从选区建画布 / 画布导入用 `mapSegments(e,dx,dy)` 平移；`Market.vue` 缩略图用各段顶点做折线近似。

约定：默认段线型为「直线」，右键选过之后后续段沿用，再右键即可换；右键位置决定曲线/圆弧弯向（落在弦上则用默认弯向）；旧的一条线拖拽创建手势被点击式取代。
验证：`npm run build`（vue-tsc + vite）通过；从真实组件源码抽函数注入 stub 跑 109 项断言（最近边点 / 三类路径 / 真圆弧圆心与 sweep / via 弯向 / 完整绘制流程 / 锚点跟随 / 各类手柄拖动 / 三种线型拆段 / 线型切换清理 / SVG A 与采样一致）全过；store 缓存 22 项断言（旧后端保存与刷新、逐条独立、清除不复活、服务端值优先、旧字符串格式兼容、脏数据兜底）全过；后端模型 AST 校验通过。**后端需重启才能把 `segments` 持久化到服务端**，未重启时靠本地缓存维持。

## 修复与增量：锚点显现 / 中点吸附 / 分段「垂线」线型

需求：锚点不再被节点盖住，但只在鼠标靠近时可见；靠近节点四边中点时自动吸附；分段右键菜单新增「垂线」＝与上一段线垂直的直线，垂足是上一段末尾（不是直角折线）。

实现（`CanvasBoard.vue`，另改 `backend/api/canvases.py` / `frontend/src/stores/canvas.ts` 注释）：
- 控制柄从 `.edge-layer`（在节点之下，锚点被节点背景与命中区盖住）拆到独立 `.handle-layer`（z-index 7 压在节点之上；层 `pointer-events:none`，只有 `.edge-handle-hit` 接收）。绘制预览的起点 / 顶点 / 当前落点圆点也移到该层。
- 新增 `pointerCanvas`（window mousemove 写画布坐标、根元素 `@mouseleave` 清空）；`visibleHandles` 按「鼠标到锚点屏幕距离 ≤ 26px / scale」显现锚点，悬停连线 / 拖动仍显示全部柄；平时画布上一个锚点都不显示。
- `snapToSideMid(r,p)`：四条边中点一起比，屏幕 10px 内返回 `{side,t:0.5}`；`nearestAnchor`（拖锚点）与 `closestEdgeAnchor`（起笔 / 收笔）都接入，阈值按 `scale` 换算成画布单位。
- 垂线 `SegType='vert'`：`ctrl[0]` 存单位法线（**方向向量**，复制 / 拖节点时不能平移，见 `mapSegments` 与 `dragSegments.type`）；方向由 `normalOf(segEndTangent(...))` 按上一段末端切向实时算（直线取弦、曲线取 `end-ctrl[1]`、圆弧取终点切线），第一段用起点锚点出边法线。落点由 `projectOnNormal` 投影成垂足；最后一段 end 是节点锚点，`vertBuilt` 画「垂线主体 + 连接短线」保证仍连到节点。`computeMixedEdge` / `drawPath` 逐段推进末端切向，上一段被编辑后垂线自动保持垂直；拖顶点、拆段、复制都保持该约束。
- 顺手修正 `confirmDrawSegment` 第二段起的 p0（原来误用起点锚点，会把曲线控制点按错起点烘焙）。

验证：`npm run build` 通过；173 项源码抽取断言（四边中点吸附 × 两个函数 + scale 换算、锚点靠近可见 / 远离隐藏 / 悬停与拖动、垂线几何与法线、完整绘制流程、方向动态重算、顶点拖动投影、拆段保留法线、复制不平移方向、模板层级静态检查）全过；store 22 项与后端 AST 回归通过。`EdgeSegment.type` 是 str 无枚举，本次只加取值、无需重启后端；`segments` 字段本身的持久化仍需此前那次重启。
